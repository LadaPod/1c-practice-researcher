# Описание проекта

Структура — по уроку курса «1 Практический Клод» (раздел «Как оформить описание проекта»).

## Название

1C Practice Researcher (Поиск практики по 1С)

## Проблема

По нетиповым вопросам 1С:ERP официальной документации часто недостаточно — реальные решения находятся в обсуждениях форумов и статьях специалистов-практиков. Искать это руками долго: нужно вручную перебирать несколько площадок, отделять актуальное от устаревшего, проверять достоверность.

## Пользователь

Консультант по 1С:ERP/Бухгалтерии — в первую очередь сама Нонна, с прицелом со временем поделиться инструментом с коллегами-консультантами.

## Основная функция

На входе — любая рабочая задача (проблема клиента, тема статьи или просто вопрос), по возможности версия/редакция 1С и текст с портала ИТС.

Если данных мало — агент сначала уточняет (версию/релиз, точный текст ошибки, при необходимости — конкретный объект программы), а не ищет вслепую.

Дальше ищет по двум источникам:
- собственная папка уже подтверждённых на практике причин и решений (`Ошибки и решения (проверенные на практике)`, проект «Консультант 1С») — вдруг вопрос уже разобран;
- внешний круг проверенных источников (форумы, статьи, разборы коллег и конкурентов) плюс вставленный вручную текст ИТС.

На выходе — структурированная таблица находок.

## Формат результата

Краткий вывод сверху + таблица находок (источник / дата или релиз / полнота ответа / надёжность источника / практическая выжимка). Если практики по теме почти нет — честно об этом сказано, а не выдуман ответ.

## Минимальный функционал (реализовано в MVP)

- Уточняющие вопросы при нехватке данных (версия, текст ошибки, объект программы)
- Поиск по кругу проверенных источников (форумы, статьи, разборы коллег)
- Учёт вставленного вручную текста ИТС как источника
- Ранжирование находок по надёжности источника
- Проверка собственной папки уже подтверждённых причин перед новым поиском, с предложением её пополнить

**В планах, не в MVP:** более широкий круг источников по мере накопления опыта; объединение со скиллом «сводка-изменений-в-учете» (мониторинг обновлений регламентированного учёта).

## Технологии

Claude Code — субагент и скилл оформлены как текстовые инструкции (Markdown), а не традиционный код на языке программирования. Инструменты субагента — только WebSearch и WebFetch (поиск и чтение веб-страниц), без доступа к файлам и командной строке.
